**NotasMave** is a web application designed to create, store, and retrieve personal notes with client-side AES encryption. Built with Python, Flask, SQLite, HTML, CSS, and JavaScript, it provides a simple interface for managing written information.

🌐 **Live Demo:** [notas-mave.vercel.app](https://notas-mave.vercel.app/)

## Features

- 🔐 **Client-side encryption:** note content is encrypted using AES before being sent to the backend.
- 📝 **Create notes:** save notes with a unique name and custom content.
- 🔎 **Retrieve notes:** search for existing notes by name.
- 🔑 **Password-based decryption:** use the provided password to decrypt and read a note.
- 🗄️ **Persistent storage:** store notes in an SQLite database through Flask-SQLAlchemy.
- 🖥️ **Web interface:** interact with notes through HTML forms and JavaScript.
- 🚫 **Unique note names:** prevent creating multiple notes with the same name.

## 🚀 Getting Started

### Prerequisites

Make sure you have installed:

- Python 3
- pip
- Git

### 1. Clone the repository

```bash
git clone https://github.com/HanzMaverick/NotasMave.git
cd NotasMave
```

### 2. Create a virtual environment

**Windows:**

```bash
python -m venv .venv
.venv\Scripts\activate
```

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Run the application

```bash
python app.py
```

Open your browser and visit:

```text
http://127.0.0.1:5000
```

The application initializes its database tables when the Flask application starts.

## 🔄 How It Works

### Creating a note

1. Enter a unique note name.
2. Provide a password and the content of the note.
3. The browser encrypts the content using CryptoJS and AES.
4. The encrypted content is sent to the Flask backend.
5. The backend stores the note in the SQLite database.

### Retrieving a note

1. Enter the name of an existing note.
2. Provide the password used when creating it.
3. The application retrieves the encrypted content.
4. The browser attempts to decrypt the content using the provided password.
5. If decryption succeeds, the original note is displayed.

## 🔌 API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/` | Displays the main search page |
| `GET` | `/search` | Displays the note search page |
| `GET` | `/admin/save` | Displays the note creation interface |
| `POST` | `/save-note` | Creates and stores a note |
| `GET` | `/get-note/<note_name>` | Retrieves a note by name |
| `POST` | `/edit-note` | Updates an existing note's content |

### Example: Save a note

**Request:**

```http
POST /save-note
Content-Type: application/json
```

```json
{
  "name": "My Note",
  "content": "ENCRYPTED_CONTENT"
}
```

**Successful response:**

```json
{
  "message": "Nota guardada exitosamente."
}
```

The `content` field should contain the encrypted string generated by the client.

## 🔒 Security Considerations

NotasMave demonstrates client-side encryption and password-based access to note content. However, the current implementation should not be considered production-ready for sensitive information.

Potential improvements include:

- Implement proper authentication and authorization.
- Validate note ownership and password verification on the server.
- Review the AES key derivation process and use a secure password-based key derivation function.
- Add HTTPS enforcement and CSRF protections where applicable.
- Avoid exposing sensitive information through API responses or logs.
- Remove debug mode from production deployments.
- Review database configuration and persistence for the deployment environment.

**Important:** The current backend does not validate the supplied password when retrieving a note. Decryption is attempted in the browser, and the `/edit-note` endpoint accepts a `password` field without verifying it. The existing `editable` flag is also not sufficient as an authorization mechanism. These behaviors should be addressed before using the application to store confidential information.
